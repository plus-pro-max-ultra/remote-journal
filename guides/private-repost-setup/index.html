私人轉貼工作台
免費方案設定指南

只教你設定，不替你改帳號。公開文章維持免登入；獨立工作台只讓指定帳號進入。

繁體中文English官方依據

免費不等於不用付款資料。Cloudflare 官方目前說 Zero Trust Free 也要填付款資料，但不收費。不願留資料、出現非 $0 金額，或選項與本頁不同時，先停下來。

1. 先分清楚兩個帳號

Cloudflare 承載帳號負責放網站；Google 登入帳號負責證明誰可以進去，兩者可以不同。先登入 Cloudflare，打開「Compute → Workers & Pages」。若你要沿用正式站帳號，必須看見 journal-for-far。若看見「No projects found」，就不是目前可管理正式站的帳號，先不要改正式站設定。

也可以把工作台放在另一個 Cloudflare 帳號，正式站只放入口連結。這不需要搬移正式站。本文採這個「獨立工作台」方向，避免把一般讀者一起擋在登入畫面外。

2. 確認費用，再設定 Zero Trust

  1. 在選定的 Cloudflare 帳號打開「Compute → Workers plans」。確認 Free / $0 / Current plan。不要按 Upgrade。
  2. 打開「Zero Trust」。若還沒有組織，依畫面選一個 team name。這會形成你的 cloudflareaccess.com 登入網域，記下完整值。
  3. 只選 Zero Trust Free。官方目前列出最多 50 位使用者的 $0 方案。若任何確認頁金額不是 $0，停止。
  4. 官方目前說：Free 方案仍須填付款資料，但不收費。 若你不願留下付款資料，停在這一步即可。本文不要求你填卡，也沒有替你開通。不要在訊息、GitHub 或本頁輸入卡號。

Workers Free 與 Zero Trust Free 是兩個不同檢查，看到前者 $0 不代表後者已開好。介面名稱可能調整，以實際確認畫面和下方官方文件為準。

3. 設定 Google 登入

如果你不需要「直接用 Google 登入」，可先停下討論 email 驗證碼方案。不要為了省步驟，把允許範圍改成所有 Gmail 使用者。

  1. 在 Google Cloud Console 選擇或建立用於此登入的專案，進入 Google Auth Platform／APIs & Services 的 OAuth 同意畫面。
  2. 填應用程式名稱及聯絡 email。個人 Gmail 使用 External audience；測試模式若要求 test users，只加入你自己準備登入的 email。這是應用程式受眾設定，不等於工作台會讓所有 Google 帳號進入。
  3. 建立 OAuth Client，類型選 Web application。
  4. Authorized JavaScript origins 填你在上一步取得的 team 網域：https://<你的-team-name>.cloudflareaccess.com。
  5. Authorized redirect URIs 填：https://<你的-team-name>.cloudflareaccess.com/cdn-cgi/access/callback。替換整段預留文字，不要原樣貼上。
  6. 取得 Client ID 與 Client secret。前往 Cloudflare「Zero Trust → Integrations → Identity providers → Add new identity provider → Google」，將兩者分別填入，儲存，再按 Test 測試。

Client secret 是密碼等級的機密。 只在 Google 與 Cloudflare 的官方設定欄位之間使用。不要貼到聊天、公開 repo、HTML、圖片或轉貼內容。不要把 Google 密碼填進 Cloudflare 的 Client secret 欄位。

此測試只確認 Google 能回傳你的身分；下一步仍要限制誰能進入。登入 Cloudflare Dashboard 的「Continue with Google」也不等於這組工作台登入已設定完成。

4. 只保護獨立工作台，不鎖正式站

先確認已有獨立的工作台 Worker。 若尚未建立，這裡可以暫停。Access 是門禁，不會自動生成文章清單、複製功能或轉貼頁；那些仍需要製作工作台程式。先不要為了試門禁去鎖 journal-for-far。

  1. 在「Workers & Pages」選擇獨立工作台，核對名稱，不是讀者使用的正式站。
  2. 進入「Access → Protect this Worker behind Access」。範圍選 All traffic，讓正式網址與預覽網址都受保護；不是只選 Previews only。
  3. 到「Zero Trust → Access controls／Access → Applications」打開這個應用程式，檢查政策。
  4. 建立 Allow 政策：Include → Emails 只填你允許的完整 Google email；再加 Require → Login Methods → Google（選你剛建立的提供者）。其餘人維持預設拒絕。
  5. 登入選項只保留預定的方式。確認沒有 Everyone、整個 @gmail.com、Bypass 或意外開放的第二條 Allow 規則。多個 Include 條件可能是「符合任一個」，不是「全部符合」。

不要使用「Protect all Workers」做這件事，也不要對公開正式站開 All traffic。隱藏按鈕、秘密網址或 noindex 都不能代替門禁。

5. 測試通過，才放正式站入口

  1. 無痕／登出狀態打開工作台：應先要求登入，不能讀文章清單、資料或匯出檔。
  2. 用允許的 Google 帳號登入：應能進入。再用另一個帳號測試：應被拒絕。
  3. 直接打開工作台資料、複製輸出、預覽與其他可達網址：都不能繞過登入。不要只測首頁。
  4. 登出、登入過期與離線後，再確認管理內容不被頁面或離線快取繼續提供。工作台不應使用正式站的離線快取，也不應載入廣告或追蹤程式。
  5. 再開一般正式站文章：應繼續免登入。確認沒鎖錯站，才加入工作台入口。

工作台只放已審完、確實同步正式站的文章。引用與來源文字在「轉貼輸出副本」裡轉成原始來源直連，正式文章閱讀版不必改。公開 repo 裡的文章仍是公開的；門禁保護的是工作台，不能把已放在公開 repo 的私人備註變成機密。

6. 需要協助時，傳畫面，不傳機密

可以傳「你在哪一頁、按鈕名稱、錯誤文字」，或遮住機密後的截圖。若畫面要求付費、金額不明，或你不想留下付款資料，停止即可。設定過程不需要把 Google 密碼、Client secret、卡號或登入 cookie 傳給任何人。

目前這是一份設定指南，不是已開好的工作台。 帳號設定與文章轉貼程式尚未因這份指南而建立；外部部落格貼上格式也還要依平台測試。

Private reposting workspace
Free-plan setup guide

Instructions only. Keep the public journal open; protect a separate read-only workspace. This guide contains no account-specific secrets and does not activate services.

1. Separate hosting from identity

The Cloudflare account hosts the workspace. The Google account identifies the person allowed to enter. They can differ. In Workers & Pages, an account used to manage the official site must show journal-for-far. An empty account does not have that project. A separate workspace can live in another account, with only an entrance link on the official site. Do not move the public site.

2. Check both free plans

Confirm Workers plans shows Free / $0 / Current plan. For a new Zero Trust organization, choose a team name and Zero Trust Free only. Cloudflare currently lists a $0 plan for up to 50 users. Its setup documentation says payment details are required even on Free, with no charge. Stop if you do not want to leave payment details, or if any price is not $0. No upgrade or card submission is required by this guide. Workers Free does not mean Zero Trust is already configured.

3. Connect Google

In Google Cloud Console, choose/create the OAuth project and consent screen. Personal Gmail uses an External audience; add only your own test user when requested. Create a Web application OAuth client. Set the JavaScript origin to https://<your-team-name>.cloudflareaccess.com and redirect URI to the same origin followed by /cdn-cgi/access/callback. Use your actual team name. In Cloudflare Zero Trust → Integrations → Identity providers, add Google, enter the client ID and client secret, save and Test. Keep the secret only in the official settings. It is not your Google password. Cloudflare Dashboard Google sign-in is separate from this workspace identity provider.

4. Protect only the workspace

A separate workspace Worker must exist first. Access does not build the article library or copy function. On that Worker, use Access → Protect this Worker behind Access → All traffic. Review its Access application policy: Allow, Include exact Emails, Require Login Methods Google. Do not allow Everyone, @gmail.com, or a Bypass. Extra Include rules may be OR conditions. Do not apply All traffic to the public journal Worker, or Protect all Workers to the account.

5. Test before linking

Test logged-out access, the allowed account, a denied account, direct data/export endpoints, previews, other reachable hostnames, logout, session expiry and offline behavior. Public articles must remain open. Keep private pages out of offline caches and tracking scripts. Only reviewed and officially synced articles belong here; copy output links citations directly to original sources. A public repository is not private storage. The workspace and blog-specific paste support are not yet built or tested.
